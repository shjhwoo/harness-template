# 하네스 엔지니어링 시스템 구축 요청용 프롬프트

아래 프롬프트를 그대로 다른 AI에게 입력해 하네스 엔지니어링 시스템 구축을 요청하세요.

---

너는 시니어 AI/소프트웨어 아키텍트다.  
목표는 **대규모·고신뢰·반복실행 가능한 하네스 엔지니어링(Harness Engineering) 시스템**을 설계하고, 실제로 동작 가능한 형태로 구현하는 것이다.

아래 요구사항을 반드시 모두 만족해라.

## 1) 최종 산출물
- 실행 가능한 저장소 구조(디렉터리 트리, 핵심 파일, 설정 파일)
- 하네스 실행 엔진(입력 → 실행 → 검증 → 채점/판정 → 리포트)
- 테스트 케이스/시나리오 정의 스키마(JSON/YAML)
- 평가 루브릭(정확성, 안정성, 성능, 보안, 비용)
- 결과 리포팅(요약 + 상세 로그 + 재현 정보)
- 운영 가이드(로컬/CI 실행법, 장애 대응, 확장 방법)

## 2) 핵심 설계 원칙
- **재현성**: 동일 입력에서 동일 결과를 보장(시드 고정, 버전 고정, 환경 고정)
- **관찰 가능성**: 모든 단계에 구조화 로그/메트릭/아티팩트 저장
- **결정적 검증 우선**: 가능하면 deterministic check를 먼저 수행
- **격리 실행**: 샌드박스/권한 최소화/네트워크 정책 명시
- **확장성**: 케이스 추가, 평가기 추가, 모델/도구 교체가 쉬운 플러그인 구조
- **실패 친화성**: 실패 유형 분류(입력오류/실행오류/검증오류/시스템오류)와 자동 재시도 정책

## 3) 시스템 아키텍처(필수 컴포넌트)
1. `Case Registry`: 테스트 케이스 메타데이터/버전 관리
2. `Runner Orchestrator`: 실행 큐잉, 병렬 처리, 타임아웃/재시도
3. `Execution Sandbox`: 격리 실행 환경
4. `Verifier/Evaluator`: 정오 판정 + 품질 평가
5. `Scoring Engine`: 가중치 기반 종합 점수 계산
6. `Report Generator`: 사람/기계 친화 리포트 생성(JSON + Markdown)
7. `Audit Store`: 입력/출력/로그/환경정보/seed 저장

## 4) 구현 요구사항
- 언어/프레임워크 선택 이유를 먼저 제시하고 구현 시작
- 최소 동작 가능한 MVP를 먼저 완성 후 확장
- CLI 제공 예시:
  - `harness run --suite smoke`
  - `harness run --case case_001 --seed 42`
  - `harness report --run-id <id>`
- 설정 파일(`config.yaml`)에서 타임아웃, 병렬도, 재시도, 스코어 가중치 조정 가능
- 실패 시 에러코드 표준화 및 사람이 이해할 수 있는 메시지 제공

## 5) 검증 및 품질 보증
- 단위 테스트 + 통합 테스트 + 회귀 테스트 구성
- 골든 테스트(기대 출력 고정)와 변동 허용 테스트(허용 오차 기반) 분리
- CI 파이프라인에서 자동 실행되도록 구성
- 성능 기준(예: N개 케이스 처리 시간)과 최소 합격선 정의
- 보안 점검 항목(명령 실행, 파일 접근, 비밀정보 노출) 포함

## 6) 출력 형식(반드시 이 순서)
1. 아키텍처 요약(다이어그램 설명 포함)
2. 디렉터리 구조
3. 핵심 코드(파일별)
4. 실행 방법(로컬/CI)
5. 테스트 전략 및 실제 테스트 코드
6. 샘플 실행 결과(성공/실패 각각)
7. 확장 로드맵(단기/중기/장기)
8. 한계와 리스크, 대응책

## 7) 작업 방식 제약
- 임의 생략 금지: 불확실한 부분은 “가정”을 명시하고 진행
- 보안 취약한 구현 금지(셸 인젝션, 경로 순회, 하드코딩 비밀값 등)
- 설명만 하지 말고, 반드시 **실행 가능한 코드/설정/테스트**를 제시
- 각 선택(기술, 구조, 정책)에 대해 짧고 명확한 근거 제시

이제 위 조건을 충족하는 **실행 가능한 하네스 엔지니어링 시스템**을 단계적으로 설계·구현해라.
